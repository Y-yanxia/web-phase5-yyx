## 问题一：那四个 yml 是干什么的？

**一句话：**
> 这四个 yml 让 GitHub 在我每次推送代码时自动做四件事：跑测试、把网页上线、打容器镜像、部署备用后端，
> 完成后在提交记录上留一个绿勾。

**口语版：**
> 可以理解成我请了四个自动工人，代码一提交它们就分别去检查、上线、打包、备份，干完给我盖个绿勾。

**正式版：**
> 这是四条 CI/CD 流水线，把测试、前端发布、镜像构建、备用后端部署都交给 GitHub 自动执行。

| 文件 | 什么时候跑 | 做什么 |
|---|---|---|
| `ci.yml` | 每次 push / PR | 装依赖 + 跑 24 条测试（16 接口 + 8 工具） |
| `pages.yml` | 推 main | 复制 public/ → 注入 `API_BASE` → 发布到 GitHub Pages |
| `docker.yml` | 推 main / tag | 构建镜像 → 推 ghcr 与阿里云 ACR → 容器内冒烟 |
| `worker.yml` | 改 worker/ | 建 D1 表 → 推 Key → 部署 Worker（没配密钥则跳过） |

## 问题二：每一部分是干什么的？

| 部分 | 一句话概括 |
|---|---|
| `public/` | 前端页面：让用户看见并操作清单，不用编译，浏览器直接跑 |
| `server/` | 后端全部代码：收请求、校验参数、读写数据库、调大模型 |
| `worker/` | 同一套接口的另一种实现，准备跑在云端函数上 |
| `tests/` | 24 条自动化测试，改完代码跑一次就知道有没有破坏约定 |
| `scripts/` | 辅助脚本：灌数据、打接口、自动点页面、截图、恢复线上 |
| `docs/` | 所有说明与证据：接口表、抓包、事故复盘、周记、答辩稿 |
| `.github/workflows/` | 四条自动化流水线：测试、上线、打包、部署 |
| `README.md` | 项目门面：简介、技术栈、运行步骤、截图、已知问题 |
| `package.json` | 依赖清单 + 命令入口 |
| `package-lock.json` | 锁死依赖版本，保证环境一致 |
| `.env.example` | 环境变量模板（值都是空的） |
| `.env` | 真实 Key，只在本机、被 git 忽略 |
| `.gitignore` | 提交黑名单：node_modules、.env、数据库文件 |
| `.gitattributes` | 统一换行、标记二进制 |
| `Dockerfile` | 打成镜像，一条命令换机器跑 |
| `.dockerignore` | 构建时排除无关文件 |
| `docker-compose.yml` | 一键起服务（端口/环境变量/数据卷/健康检查） |
| `render.yaml` | Render 部署描述（要绑卡，未启用） |
| `wrangler.toml` | Cloudflare 配置（等密钥） |
| `*.code-workspace` | VS Code 工作区：7 个任务 + 2 个调试配置 |
| `答辩话术.docx` | 打印版答辩稿 |

**总纲：** 代码分三层——能跑的（public/server）、能验的（tests/scripts/workflows）、能讲清的（docs/README/答辩稿）。

## 问题三：关键代码在哪里？

### 一、工具调用（最核心）

| 看点 | 位置 | 解决什么 |
|---|---|---|
| 两轮工具循环 `liveAgent()` | `server/ai/agent.js:L270` | 模型要工具 → 后端执行 → 回填 → 再问一次；最多 3 轮 |
| 工具定义 `TOOL_DEFINITIONS` | `server/ai/tools.js:L15` | description 是模型的使用说明书 |
| 执行器 `executeTool()` | `server/ai/tools.js:L91` | 唯一真正改库的地方 |
| 日期注入 `currentDatePrompt()` | `server/ai/agent.js:L30` | 不告诉它日期就会把“明天”算错 |
| 流解析 `streamCompletion()` | `server/ai/deepseek.js:L44` | 拆文字增量与工具参数分片 |

### 二、流式与停止生成

| 看点 | 位置 | 解决什么 |
|---|---|---|
| 断开感知 `res.on('close')` | `server/routes/chat.js:L95` | 用户停止时掐上游，省 token |
| SSE 三件套 | `server/routes/chat.js:L85` | 防反向代理缓冲 |
| 前端流解析 `readSse()` | `public/app.js:L568` | 按空行切事件、拼半包 |
| 发消息 `sendMessage()` | `public/app.js:L602` | 工具卡片、AbortController |

### 三、接口与数据

| 看点 | 位置 | 解决什么 |
|---|---|---|
| 中间件顺序 | `server/app.js:L24` | CORS 在前、错误处理在最后 |
| 全局错误兜底 | `server/app.js:L74` | 异常都回 JSON |
| `asyncHandler` | `server/lib/http.js:L20` | Express 4 不捕获 async rejection |
| 参数校验 `parseDue` | `server/routes/items.js:L48` | undefined/null/'' 三态 |
| 建表与查询 | `server/db.js:L32` | node:sqlite + WAL + 预编译 |
| 三态渲染 `renderList()` | `public/app.js:L247` | loading / empty / error 判断顺序 |

### 只记五个

1. `agent.js` 的 `liveAgent()` —— 工具循环
2. `chat.js` 的 `res.on('close')` —— 停止生成的原理
3. `http.js` 的 `asyncHandler` —— 为什么不包会崩
4. `items.js` 的 `parseDue` —— 真实 bug 的修复痕迹
5. `app.js` 的 `renderList()` —— 三态与“数据来自接口”

## 用法建议

- 答辩前 5 分钟：只看「问题一的标准答法」和「只记五个」。
- 被问“讲讲这段代码”：先说解决什么问题 → 再讲实现 → 最后补一句踩过的坑。
- 被问没准备的：承认没验证过，说出理解，比硬编安全。

## 附录：每个文件是干什么的

### public/ — 前端

| 文件 | 作用 |
|---|---|
| `index.html` | 页面骨架：头部、两个 Tab、清单面板、AI 面板、页脚 |
| `style.css` | 全部样式：设计变量、组件样式、375px 适配 |
| `app.js` | 全部交互：状态管理、渲染、fetch、SSE 流式、工具卡片 |
| `config.js` | API 地址配置（本地同源；部署时被 Actions 注入线上地址） |
| `404.html` | 真 404 页（服务端返回 404 状态码） |

### server/ — 后端

| 文件 | 作用 |
|---|---|
| `index.js` | 进程入口：监听端口、打印启动信息、优雅退出 |
| `app.js` | 中间件流水线：CORS → JSON → 日志 → 路由 → 静态 → 404 → 错误兜底 |
| `config.js` | 配置中心：唯一读 .env / 环境变量的地方 |
| `db.js` | 数据层：建表、WAL、预编译语句，所有 SQL 都在这 |
| `lib/http.js` | 统一返回 ok/fail、asyncHandler、手写 CORS 中间件 |
| `lib/errors.js` | 业务错误类型（带状态码与业务码） |
| `routes/items.js` | 清单 CRUD + 四个参数校验函数 |
| `routes/chat.js` | SSE 对话入口：响应头、心跳、断开感知、错误事件 |
| `ai/deepseek.js` | 调 DeepSeek、解析上游流、把错误翻译成人话 |
| `ai/agent.js` | 会话上下文 + 两轮工具循环 + 无 Key 时的 mock |
| `ai/tools.js` | 三个工具的 JSON Schema + 唯一真正改库的执行器 |

### worker/ — 另一套后端（Cloudflare Workers + D1）

| 文件 | 作用 |
|---|---|
| `index.js` | Worker 路由入口：手写路由、CORS、参数校验 |
| `db.js` | D1 数据层：全异步 API，多了对话历史表操作 |
| `chat.js` | Worker 版 SSE（TransformStream）+ 工具循环，历史落 D1 |
| `tools.js` | Worker 版工具定义与执行器 |
| `schema.sql` | 建 items 与 chat_messages 两张表 |

### tests/ — 自动化测试

| 文件 | 作用 |
|---|---|
| `api.test.js` | 16 条：创建/校验/更新/删除/404/400/统计/SSE 全链路/多轮上下文 |
| `tools.test.js` | 8 条：工具执行器边界（空标题、未知工具、多条命中、过滤） |

| 文件 | 作用 |
