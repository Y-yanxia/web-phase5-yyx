# 代码导读：每一部分是干什么的

> 配合 `web-phase5-yyx.code-workspace` 使用：VS Code 打开工作区后，边看这份文档边点文件。
> 每一节按「**职责 → 关键代码 → 为什么这么写 → 答辩怎么讲**」四段。

---

## 0. 全局：一次请求是怎么流动的

```
浏览器 public/app.js
   │  fetch('/api/items')
   ▼
server/index.js        只负责启动（listen 端口）
   └─ app.js           中间件流水线：CORS → JSON 解析 → 日志 → 路由 → 静态页 → 404 → 错误兜底
        ├─ routes/items.js  清单的增删改查（校验也在这）
        │     └─ db.js      只有这里碰 SQL（node:sqlite）
        └─ routes/chat.js   对话（SSE）
              └─ ai/agent.js     会话历史 + 两轮工具循环
                    ├─ ai/deepseek.js  跟模型说话（流式解析）
                    └─ ai/tools.js     工具定义 + 真正执行
                          └─ db.js     工具也是改同一张表
```

**记住这条线**：页面只认 `{code,data,msg}`；数据库只有 `db.js` 能碰；模型只能"说"，执行永远在 `tools.js`。

## 2. 后端逐文件

### `server/index.js` — 进程入口（20 行）

- **职责**：起服务、打印启动信息、处理 SIGINT/SIGTERM。
- **关键**：`app.listen(config.port)`；`server.close()` 优雅退出。
- **为什么**：业务逻辑全在 `app.js`，这样测试里可以 `createApp()` 挂到随机端口，不用起真进程。

### `server/app.js` — 请求流水线（最重要，答辩常被点开）

顺序就是处理顺序，改顺序前先想清楚影响：

| 顺序 | 中间件 | 作用 | 踩过的坑 |
|---|---|---|---|
| 1 | `corsMiddleware` | 白名单来源加 `Access-Control-Allow-Origin`，`OPTIONS` 直接 204 | 必须在业务路由**之前**，否则预检被 404 |
| 2 | `express.json({limit:'32kb'})` | 解析 JSON 请求体 | 限额小一点顺手挡超大包 |
| 3 | 访问日志 | 打印 `方法 路径 → 状态码 耗时` | 演示时能直接看到前端发了什么 |
| 4 | `/api/health` | 健康检查（含模式、运行时长、统计） | Render/隧道靠它判断活没活 |
| 5 | `/api/items`、`/api/chat` | 业务路由 | —— |
| 6 | `express.static('public')` | 托管前端 | 同源部署时连 CORS 都不用 |
| 7 | `/api` 404 | 接口不存在返回 JSON | 不能掉进 HTML 错误页 |
| 8 | 非接口 404 | 返回 404.html + **404 状态码** | 一开始给的是 200，等于"软 404" |
| 9 | 错误中间件 | `AppError` → 对应状态码；其他 → 500 JSON | 不泄漏堆栈，不把 HTML 甩给前端 |

### `server/config.js` — 配置中心

- **职责**：读 `.env`、解析环境变量、导出 `config` 对象。
- **关键**：手写 20 行 `.env` 解析（不引 dotenv）；`aiMode` 由"有没有 Key"推导。
- **为什么**：全项目只有这里碰 `process.env`，其他模块只认 `config`，一眼能看出有哪些配置项。
- **答辩讲法**：少一个依赖少一个部署坑；配置收敛到一个文件，线上换环境不用改代码。

### `server/db.js` — 唯一碰 SQL 的地方

- **职责**：建表、预编译语句、增删改查、统计。
- **关键**：
  - `new DatabaseSync(config.dbFile)`（Node 24 内置 `node:sqlite`，不用 better-sqlite3）
  - `PRAGMA journal_mode = WAL`：读写不互相阻塞
  - `db.prepare(...)` 预编译：SQL 只解析一次
  - `normalize()`：SQLite 没有布尔，把 0/1 统一成数字，null 的 due 统一成 `null`
- **为什么**：把"数据长什么样"关在一个文件里，接口层只认对象；换数据库只改这一个文件。

### `server/lib/http.js` — 三个小工具

| 导出 | 作用 |
|---|---|
| `ok(res, data, msg)` | 成功响应，固定 `code: 0` |
| `fail(res, status, code, msg)` | 失败响应，固定 `data: null` |
| `asyncHandler(fn)` | 包住 async 路由，把 rejection 交给错误中间件 |
| `corsMiddleware(origins)` | 手写跨域：命中白名单才加头，`OPTIONS` 直接结束 |

**答辩重点**：`asyncHandler` 不是装饰——Express 4 不捕获 async 里的 rejection，不包的话一次数据库异常就能把进程带走。

### `server/lib/errors.js` — 错误类型

- `AppError(message, { status, code })`：带 HTTP 状态码和业务码。
- `badRequest()` / `notFound()`：两个快捷构造。
- **作用**：路由里 `throw badRequest('缺少必填字段：title')`，错误中间件统一转成 400 JSON。

### `server/routes/items.js` — 清单接口（校验最密的地方）

- **路由**：GET 列表 / GET 统计 / GET 单条 / POST 新增 / PUT+PATCH 修改 / DELETE 删除。
- **校验函数**：`parseId`、`parseTitle`、`parseDue`、`parseDone`。
- **关键细节**：
  - `parseDue` 里 `undefined/null/''` 三种都算"没填"——漏掉 `undefined` 就会让"不填日期"反而 400（真实 bug，测试抓的）。
  - PUT 和 PATCH 共用 `updateHandler`，PATCH 只是语义别名。
  - `?fail=1` 是开发开关，只在非 production 生效，用来截"错误态"。
- **答辩讲法**：参数校验放在路由层，业务层不用再防御；返回 400 而不是 500，是因为"你少传了字段"不是"服务器坏了"。

### `server/routes/chat.js` — 对话入口（SSE）

- **职责**：校验入参 → 设 SSE 头 → 调 `runAgent()` → 把事件写回前端。
- **关键代码**：
  - `res.setHeader('Content-Type','text/event-stream')` + `X-Accel-Buffering: no`
  - `res.flushHeaders()`：先把头发出去，否则前端要等
  - `res.on('close', ...)`：**用户点停止时掐上游**（不是 `req.on('close')`，那个请求体读完就触发）
  - 心跳 `: ping` 每 15 秒：防止中间层把空闲连接掐了
  - 事件类型：`meta` / `delta` / `tool_call` / `tool_result` / `done` / `aborted` / `error`
- **答辩讲法**：SSE 是单向的，浏览器断开时服务端收不到通知，必须靠 `res` 的 close 事件感知。

### `server/ai/deepseek.js` — 跟模型说话

- **职责**：发请求（带 tools）、解析上游 SSE、把错误翻译成人话。
- **关键**：
  - `stream: true` + `tools` + `temperature: 0.2`（工具调用要稳，不要发挥）
  - 流解析：按 `\n\n` 切事件，只处理 `data:` 行；`delta.content` 是文字，`delta.tool_calls` 是工具调用**分片**（`arguments` 要一段段拼）
  - `translateStatus()`：401 Key 错、402 余额不足、429 限流、其他 → 上游故障
- **答辩讲法**：模型返回的工具参数不是一次性给全的，是流式碎片，必须按 index 累加。

### `server/ai/agent.js` — 编排层（工具循环在这）

| 函数 | 作用 |
|---|---|
| `SYSTEM_PROMPT` | 角色与边界：必须调工具、不编造数据、回复不超过 3 句 |
| `currentDatePrompt()` | 把"今天几号"喂给模型，否则它会把"明天"算成别的日期 |
| `getSession/saveTurn/trimHistory` | 会话历史（内存 Map），只保留最近 N 条 |
| `mockAgent()` | 没 Key 时的规则模拟：识别意图 → 调同一个 `executeTool` → 拼自然语言 |
| `liveAgent()` | **核心**：最多三轮的工具循环 |
| `runAgent()` | 按 `config.aiMode` 分流到 mock / live |

**`liveAgent()` 逐段**：

1. 拼 messages：system（含日期）+ 历史 + 用户这句话
2. 调 `streamCompletion`，边流边把文字推给前端
3. 如果没有 `tool_calls` → 结束，返回文字
4. 有 → 把 assistant（带 tool_calls）压进 messages；逐个解析参数、执行、推 `tool_call`/`tool_result` 事件、把结果以 `role:"tool"` 回填
5. 回到第 2 步再问一次（模型看着结果说人话）
6. 最多 3 轮，防止死循环烧钱

**坏 JSON 兜底**：`JSON.parse` 失败不抛，而是把错误当成失败的工具结果回填，让模型自己改参数。

### `server/ai/tools.js` — 工具定义与执行

- `TOOL_DEFINITIONS`：三个工具的 JSON Schema。
  - `add_item(title 必填, due 可选)`
  - `query_items(done 可选, keyword 可选)`
  - `complete_item(keyword 必填)`
- `executeTool(name, args)`：**唯一**真正改数据库的地方，返回 `{ ok, data, summary }`。
- **description 是模型唯一的说明书**：写"用户说『帮我记/加一条』时必须调用"，而不是"新增"。
- **答辩讲法**：模型看不见 SQL，也拿不到数据库句柄；它只能点菜，厨房在这里。

## 3. 前端逐文件

### `public/index.html` — 骨架

- 语义标签：`header / nav / main / section / footer`。
- 两个 Tab 用 `role="tablist"` + `aria-selected`（无障碍）。
- `data:` 内联 favicon —— 避免浏览器自动请求 `/favicon.ico` 在 Console 留红。

### `public/style.css` — 样式

- `:root` 里的 CSS 变量：配色、圆角、阴影、字体一处改全站。
- Flexbox 布局；`640px` 断点做手机适配。
- 关键防溢出：`box-sizing: border-box` + 子项 `min-width: 0` + 不用 `100vw`。
- `[hidden] { display: none !important }`：因为 `.btn` 自带 `display:inline-flex`，会盖掉 `hidden` 属性（真实 bug）。

### `public/app.js` — 交互（最长的一个文件，按三段读）

| 段 | 内容 | 干什么 |
|---|---|---|
| 状态 | `state` 对象 | 列表、统计、筛选、搜索词、加载/错误态、AI 模式、会话 id |
| 工具 | `api()`、`escapeHtml`、`dueLabel` | 统一请求封装（自动判断 `code!==0`）、XSS 转义、日期标签（逾期/今天） |
| 渲染 | `renderList`、`renderStats`、`showState` | 三态渲染：骨架屏 / 空态 / 错误+重试 |
| 清单事件 | 添加、勾选、删除、筛选、搜索 | 每次操作后重新 `loadItems()`，数据永远来自接口 |
| Tab | `switchTab` | 切换面板 + 记忆 hash |
| AI | `sendMessage`、`readSse`、工具卡片 | fetch + `getReader()` 逐块解析 SSE，实时渲染 |
| 启动 | `loadItems` + `loadMeta` | 进页面先拉数据与模式 |

**几个值得指的点**：

- `readSse()`：按 `\n\n` 切事件、只认 `data:` 行——和 `deepseek.js` 里的解析是同一套思路。
- `AbortController`：停止生成时 abort，后端 `res.on('close')` 感知。
- 工具卡片：收到 `tool_call` 就插入一张卡片，收到 `tool_result` 再补结果——这就是"前端能看到调了什么"。
- 三态：`state.loading` / `state.error` / `items.length===0` 三个条件决定渲染哪块。

### `public/config.js` — API 地址

- `window.__API_BASE__`：本地留空（同源）；部署时被 GitHub Actions 写成一串线上地址。
- 支持 `?api=` 临时覆盖，方便本地连线上后端调。

### `public/404.html` — 真 404

- 服务端对未知路径返回它，**状态码是 404**，不是 200 的"软 404"。

## 4. `worker/` — 另一个后端（Cloudflare Workers + D1）

同一套接口的 Serverless 实现，方便哪天不想开电脑也能有固定地址：

| 文件 | 与 Express 版的差异 |
|---|---|
| `index.js` | 路由用 URL 解析手写，没有中间件栈；校验逻辑照搬 |
| `db.js` | D1 的 API 全是 async；`prepare().bind().all()/first()/run()` |
| `chat.js` | SSE 用 `TransformStream`；历史落 `chat_messages` 表（不能用内存） |
| `tools.js` | 执行器改成 async，语义不变 |
| `schema.sql` | 建 `items` 与 `chat_messages` 两张表 |

**答辩讲法**：同一个产品，两种运行模型；Serverless 逼我把"会话历史"从内存搬进数据库。

## 6. 三条链路追踪（答辩基本就考这些）

### A. 点「添加」按钮

```
public/app.js submit 事件
  → 校验标题非空 → api('/api/items', POST)
    → server/app.js → routes/items.js POST
      → parseTitle / parseDue（不合法直接 400）
      → db.createItem()（INSERT ... RETURNING）
      → ok(res, item)
  → loadItems() 重新拉列表 → renderList()
```

### B. 说一句话「帮我加一条明天交实验报告」

```
public/app.js sendMessage
  → POST /api/chat（SSE）
    → routes/chat.js：设 SSE 头、监听 close
      → ai/agent.js liveAgent()
        → ai/deepseek.js：带 tools 请求模型，流式解析
        ← 模型返回 tool_calls: add_item({"title":"交实验报告","due":"2026-11-21"})
        → ai/tools.js executeTool() → db.createItem()（真落库）
        → 结果以 role:"tool" 回填 → 再请求一次
        ← 模型输出自然语言 "已经记下了 #12…"
  → 前端逐个 delta 渲染，工具卡片显示参数与结果
```

### C. 按 F5 刷新

```
浏览器重新加载 index.html → app.js 执行
  → loadItems() 打 /api/items
    → routes/items.js → db.listItems()（读 SQLite 文件）
  → 数据还在，因为写在磁盘上，不在内存
```

## 7. 想改某个功能，改哪里

| 需求 | 改哪里 |
|---|---|
| 加字段（比如优先级） | `db.js` 建表 SQL → `routes/items.js` 校验 → `public/app.js` 渲染与表单 |
| 加一个工具 | `ai/tools.js` 加 Schema + `executeTool` 分支（模型自动可用） |
| 换模型/换平台 | `config.js` 的 `DEEPSEEK_BASE_URL` / `MODEL` |
| 改提示词 | `ai/agent.js` 的 `SYSTEM_PROMPT` |
| 改接口地址 | `public/config.js` 或仓库变量 `API_BASE` |
| 加接口 | `routes/*.js` 挂路由 → `app.js` 注册 |
| 改样式 | `public/style.css` 的 `:root` 变量 |
