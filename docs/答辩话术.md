# 答辩话术（照着念也能过）

> 任务书原文：**能跑、能讲**。能跑 = 有线上链接；能讲 = 对着代码说清每一行在干什么。
> 答辩抽三题：① 为什么这样设计 ② 打开任意文件讲清某段代码 ③ 哪里最容易坏、你怎么发现的。
> 下面全部是口语稿，方括号里是动作提示。

---

## 一、开场（30 秒，背下来）

> 老师好，我做的是一个**能用自然语言操作的待办清单**，叫「一句话清单」。
>
> 平时记待办最烦的是步骤太多：打开 App、找输入框、打字、选日期。我想把它压成一句话——
> 对着页面说「帮我加一条明天交实验报告」，模型判断要调工具，后端真的往数据库里插一条，
> 再把结果用中文说给我听。手动增删改查也都保留，不用 AI 也能当普通清单用。
>
> 技术上：前端是原生 HTML/CSS/JS，后端 Node + Express + SQLite，模型接的 DeepSeek，
> 用 SSE 做流式、用 function calling 做工具调用。线上地址在 GitHub Pages，后端在我本机用隧道暴露。

## 三、问题一：为什么这样设计（60–90 秒）

> 我的选型只服从三个约束：**任务书的限制、免费额度、我能不能讲清楚**。
>
> **前端选原生三件套**，因为任务书明确不鼓励上框架；而且这周的目标是把「点击 → fetch → 渲染」
> 这条链讲明白，Vue 会把它藏起来。
>
> **单页 + 两个 Tab**，任务书允许用 Tab 面板切换，我就不做路由了，省下的时间给了工具调用。
>
> **后端 Node + Express**，前后端同一门语言，SSE 转发写起来最顺。
>
> **数据库用 SQLite，而且是 Node 24 内置的 `node:sqlite`**，不是 `better-sqlite3`——后者是原生模块，
> 在免费容器里要编译，很容易装不上；内置模块零依赖，`npm install` 只装 express 一个包。
>
> **流式用 SSE 不用 WebSocket**，因为对话是单向流，SSE 就是普通 HTTP，反向代理和防火墙都友好。
>
> **数据结构就一张 `items` 表**：`id / title / done / due / created_at`。
> `done` 用 0/1 是因为 SQLite 没有布尔；`created_at` 用 `datetime('now','localtime')` 做默认值，
> 这样接口层不用管时间，少一个出错的地方。
>
> 一句话总结：**没有用什么先进技术，用的都是能被讲清楚的技术。**

## 四、问题二：打开任意文件讲一段代码（选一条，90 秒）

### 路线 A（推荐）：`server/ai/agent.js` 的 `liveAgent()`

> [打开文件，指到 `liveAgent`]
>
> 这段是工具调用的核心，是个**最多跑三轮的循环**。
>
> 第一轮我把 system 提示词、历史消息、用户这句话一起发给模型，并且带上三个工具的 JSON Schema。
> 模型如果只想聊天，就直接返回文字，循环结束。
>
> 如果它返回 `tool_calls`，说明它要调工具。我先把它这条 assistant 消息（带 tool_calls）压进 messages，
> 然后**逐个执行**——注意，执行的是我自己的 `executeTool()`，模型碰不到数据库。
>
> 执行完，我把结果以 `role: "tool"` 的身份塞回去，再请求一次。第二轮模型就能看着工具结果说人话了。
>
> 这里有三个细节值得说：
> 第一，**坏 JSON 不抛异常**——`JSON.parse` 失败时我把错误当成一次「失败的工具结果」回填，让模型自己改参数，
> 而不是把整个请求挂掉。
> 第二，**前后各发一个 SSE 事件**（`tool_call` 和 `tool_result`），前端才能画出「调了什么、传了什么、结果如何」。
> 第三，**最多三轮**，最后一轮如果模型还要工具，我就不再给机会，避免死循环烧钱。

### 路线 B：`server/routes/chat.js` 的断开感知

> [指到 `res.on('close', ...)`]
>
> SSE 是单向的：用户点「停止生成」时，浏览器只是把连接断开，服务端不会收到任何通知。
> 所以我监听响应的 `close`，判断 `!res.writableEnded`——意思是「响应还没写完就被关了」，
> 那就是用户主动断的，这时 `controller.abort()` 掐掉**到 DeepSeek 的上游请求**。
> 不掐的话，用户看着已经停了，其实模型还在生成，钱还在烧。
>
> 这里有个坑：一开始我监听的是 `req` 的 `close`，结果每个正常请求刚进来就被判定成「断开」——
> 因为 Node 里 `req` 的 `close` 在**请求体读完**时就触发，不是连接断开才触发。

### 路线 C：`server/config.js`

> 全项目只有这一个文件读 `process.env`，别的模块只认 `config` 对象。
> 好处是「有哪些配置项」一眼可见，也不会某个文件偷偷写死 localhost。
> `.env` 解析是我自己写的 20 行，不引 dotenv——少一个依赖，部署时少一个可能装不上的包。

## 五、问题三：哪里最容易坏，怎么发现的（90 秒）

> 我踩了五个坑，挑两个最硬的讲。
>
> **第一个：SSE 被自己掐断。**
> 现象是前端只收到 `{"type":"meta"}`，紧接着 `{"type":"aborted"}`，一个字都没流出来；
> 但用 curl 直接打接口是正常的。定位到 `req.on('close')`——Node 的 `IncomingMessage` 在请求体读完时
> 就触发 close，所以每个正常请求都被当成「用户取消」。改成监听 `res` 的 close，并加 `writableEnded` 判断。
>
> **第二个：工具选错。**
> 我说「我还有哪些没做完」，它却调了「标记完成」，返回「没找到包含『我还有哪些没』的条目」。
> 原因是意图判断的正则里「做完」先命中了完成分支。修法是三步：先判查询再判完成、加否定词
> （没做完/未完成/还没）、这类问法自动带 `done: 0`。
>
> 另外三个一句话带过：
> **CORS** 预检没过（白名单没加前端端口，Console 里存了原文）；
> **可选字段** `undefined` 漏判，不传日期反而 400，是自动化测试抓出来的；
> **模型不知道今天几号**，把「明天」算成 2026-06-11，修法是每次请求把当前日期拼进 system 提示词。
>
> 共同规律：**都不是业务逻辑错，是边界错**——连接的生命周期、跨域策略、意图优先级、
> `undefined/null/''` 的三态。完整复盘在 `docs/incidents.md`，每条都有现象、定位、修复、验证。

## 六、十个追问（快问快答）

| 老师可能问 | 你怎么答 |
|---|---|
| 为什么不用 Vue/React？ | 任务书不建议；而且这周要能讲清 DOM 和请求，框架会把这两层藏起来 |
| 为什么用 SSE 不用 WebSocket？ | 对话是单向流；SSE 是普通 HTTP，反代友好，还能用 fetch 带 POST 参数 |
| SQLite 能撑住并发吗？ | 单机、WAL 模式、写少读多够用；要多实例就得换 Postgres，我写在「已知问题」里 |
| Key 会不会泄漏到前端？ | 只在服务端 `deepseek.js` 的请求头里；F12 看 chat 请求体只有 sessionId 和 message；仓库全历史零命中 |
| 模型不调工具怎么办？ | 五步排查：描述太短 → 没加 required → 没给强制语 → 温度太高 → 用了 reasoner 模型 |
| 工具死循环怎么办？ | 最多三轮，超了返回兜底话术 |
| 上下文太长怎么办？ | `HISTORY_LIMIT=8`，超出丢最早的；system 永远保留 |
| 为什么 mock 模式？ | 没 Key 时用规则模拟，但走的是**同一套工具执行器和同一张表**，数据链路是真的；配 Key 自动切真模型 |
| 数据会丢吗？ | 本机 SQLite 不会；换到免费云（FC）会——实例回收即清空，要挂 NAS，我实测过 |
| 有什么没做完？ | 没鉴权、没多端同步、线上后端还是隧道（电脑关机就断）。三件都写进 README 的「已知问题」，是权衡后没做 |

## 八、收尾（20 秒）

> 这周最大的收获不是学会了哪个库，而是搞清楚了一件事：**模型不会「干」，它只会「说」**。
> 真正把事做成的是那圈工具循环，和后面几条老老实实的 SQL。
> 页面能打开只是开始，能讲清每一次请求才算入门。
