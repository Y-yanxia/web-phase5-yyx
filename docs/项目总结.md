# 26 级第五阶段 · 项目总结（对照任务书）

> 依据：《26级第五阶段任务书：完善 Web + AI 应用》（6 页 PDF）
> 验收标准原文：**能跑、能讲**。能跑 = 有线上链接；能讲 = 对着代码说清每一行在干什么。

## 一、一句话

做了一个**能用自然语言操作的待办清单**：手动能增删改查，动嘴也能——说「帮我加一条明天交实验报告」，
模型判断要调工具、后端真的写进数据库、再把结果用中文说给你听；前端是原生三页，后端 Node + SQLite，
线上地址在 GitHub Pages（前端）+ Cloudflare 隧道（后端）。

## 三、技术栈

| 层 | 选型 |
|---|---|
| 前端 | 原生 HTML / CSS / JS（无框架、无构建） |
| 后端 | Node.js 24 + Express 4 |
| 数据库 | SQLite（`node:sqlite` 内置模块） |

| 部署 | GitHub Pages（前端）+ Cloudflare 隧道（后端，临时）；容器镜像已构建（ghcr / 阿里云 ACR） |
| 工程 | GitHub Actions（CI + Pages + 镜像构建）、`node:test` 24 条用例、E2E 9 项 |

## 八、答辩三问（30 秒版）

1. **为什么这样设计**：原生前端是任务书硬限制，也逼我把「点击→fetch→渲染」讲清楚；
   SQLite 用 Node 内置模块，免编译、单文件；SSE 是因为对话是单向流；工具执行器和模型解耦，
   所以 mock 和真模型共用同一条数据链路。
2. **讲一段代码**：`server/ai/agent.js` 的 `liveAgent()`——模型返回 `tool_calls`，后端执行、
   结果以 `role:"tool"` 回填、再请求一次拿自然语言总结；坏 JSON 当失败结果回填，最多 3 轮。
3. **哪里最容易坏**：连接生命周期（`req` 的 close 会误杀 SSE）、跨域预检、模型不按格式调用工具、
   可选字段的 `undefined/null/''` 三态。四条都踩过，都在 `docs/incidents.md` 里。
