## 三、问题与解决（四段原文）

### 1. 每个流式请求刚进来就被自己掐断

现象：`/api/chat` 只回 `{"type":"meta"}` 紧接着 `{"type":"aborted"}`，一个字都没流出来；curl 直连却正常。

定位：写了 `req.on('close', () => controller.abort())`。Node 里 `IncomingMessage` 的 `close` 在**请求体读完**时就会触发，不是连接断开才触发。

解决：改听 `res.on('close')`，并用 `!res.writableEnded` 区分「正常结束」和「用户断开」。

### 2. 跨域：一条请求都发不出去

原文：
```
Access to fetch at 'http://127.0.0.1:3100/api/items' from origin 'http://127.0.0.1:5055'
has been blocked by CORS policy: Response to preflight request doesn't pass access control check:
No 'Access-Control-Allow-Origin' header is present on the requested resource.
```

尝试：先用 `curl -i -X OPTIONS` 确认服务端确实没回头，排除「前端写错」。原因是 fetch 带了 `Content-Type: application/json` 触发预检，而白名单里没有 5055。

解决：`ALLOWED_ORIGINS` 加上前端来源，服务端统一加头；没有关浏览器安全策略。

### 3. 不传截止日期反而 400

现象：`POST /api/items` 只传 `{"title":"复习复变"}` 返回 400 `due 必须是 YYYY-MM-DD 格式的字符串`。

定位：`parseDue` 只判断了 `null` 和 `''`，漏了 `undefined`——`undefined !== null`，于是掉进类型检查。

解决：`if (raw === undefined || raw === null || raw === '') return null;`，并补了测试防止回归。

### 4. 模型把「明天」算成 2026-06-11

现象：接真模型后第一句「帮我加一条明天交实验报告」，`add_item({"due":"2026-06-11"})`。

定位：系统提示词里没有「今天是几号」，模型没有系统时间，只能猜。

解决：每次请求现算日期拼进 system 消息（`currentDatePrompt()`），并要求相对日期先换算；两天后再测仍准确（今天 11-22 → 明天 11-23）。

## 四、知识点（自己的话）

**HTTP 状态码**：三位数，第一位表示类别。2xx 是「服务端办成了」，4xx 是「你请求有问题」（400 参数不对、404 找不到、429 太频繁），5xx 是「服务端自己出错」。
写接口时我坚持「缺字段返回 400 而不是 500」，因为 500 会让调用方以为是服务器崩了，其实是它少传了参数。

**CORS**：浏览器为了保护用户，默认不允许 A 站点用 JS 读 B 站点的响应。放行方式是由 **B（服务端）** 返回
`Access-Control-Allow-Origin` 告诉浏览器「我允许 A」。
带 `Content-Type: application/json` 的请求会先发一个 `OPTIONS` 预检，预检不通过，真正的请求根本发不出去——
所以 Console 里看到的是 CORS 报错，但根子在服务端的响应头。

**Function Calling**：模型本身不能执行代码，它只会「说」：我要调用 `add_item`，参数是 `{"title":"..."}`。
真正查数据库、插数据的是我的后端。所以这条链路上有两个边界：模型看不到 SQL；执行器的返回值必须是 JSON，
并且要能承受模型给错参数（我这里是坏 JSON 当失败结果回填，让模型自己改）。
