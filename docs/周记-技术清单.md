# 本周技术清单：用了什么、各自起什么作用

> 周记「知识点」板块的展开版。按「前端 → 后端 → 数据 → AI → 部署 → 工程」排，每条写清：
> **用在哪、解决什么问题、为什么选它**。

## 一、前端

| 技术 | 用在哪 | 作用 |
|---|---|---|
| HTML5 语义化标签（`header/nav/main/section/footer`） | `public/index.html` | 让结构自己会说话：读屏软件能跳读、搜索引擎能理解层级，也逼我把「导航/主体/页脚」想清楚 |
| CSS 变量 + Flexbox + 媒体查询 | `public/style.css` | 一处定义配色和圆角，全站复用；640px 断点让 375px 手机上不出横向滚动条 |
| 原生 DOM + 事件委托 | `public/app.js` 的 `els.list.addEventListener` | 列表里每条都有勾选/删除按钮，事件绑在父节点上只绑一次，新增的条目自动生效 |
| 表单校验（`novalidate` + 手写规则） | 添加任务表单 | 空标题在前端就拦住并给出人话，不让它白跑一趟接口 |
| `fetch` + `async/await` | `loadItems()`、增删改 | 所有列表数据都来自接口，页面里没有一行写死的数组 |
| `ReadableStream` + `getReader()` | 对话页的 `readSse()` | 逐块读 SSE，模型吐一个字就渲染一个字，而不是等整段返回 |
| `AbortController` | 停止生成 | 点「停止」立刻断掉请求，配合后端掐上游，不再烧 token |
| `localStorage` | 生成/保存 `sessionId` | 刷新页面后还是同一个会话，3 轮上下文不断 |
| 三态渲染（loading / empty / error+重试） | `renderList()` | 网络慢、没数据、请求失败三种情况都有明确交代，不白屏 |

## 二、后端

| 技术 | 用在哪 | 作用 |
|---|---|---|
| Node.js 24 | 整个服务 | 前后端同一门语言，SSE 转发写起来最顺 |
| Express 4 | `server/app.js` | 把「解析 JSON → 跨域 → 日志 → 路由 → 静态文件 → 错误兜底」串成一条流水线 |
| 中间件顺序设计 | `createApp()` | CORS 必须在业务路由之前，否则预检请求会被 404 掉；静态文件在接口之后，避免吞掉 `/api` |
| 手写 CORS 中间件 | `server/lib/http.js` | 只给白名单来源发 `Access-Control-Allow-Origin`，`OPTIONS` 直接 204；比引 `cors` 包少一个依赖，也更容易讲清预检 |
| 统一响应封装 | `ok()/fail()` | 全站只有两个出口，前端只判断 `code === 0` |
| `asyncHandler` | 所有路由 | Express 4 不捕获 async 里的 rejection，包一层才不会因为一次数据库报错把进程带走 |
| 参数校验（手写） | `routes/items.js` | 缺字段、类型错、格式错都返回 400 + 人话；`undefined/null/''` 三态分开处理 |
| 全局错误中间件 | `app.js` 最后一段 | 任何异常都变成 `{code,data,msg}`，不把 HTML 堆栈甩给前端 |
| 环境变量集中读取 | `server/config.js` | 全项目只有这一个文件读 `process.env`，线上换配置不用改代码 |
| SSE（`text/event-stream`） | `routes/chat.js` | 单向流式输出的标准做法，比 WebSocket 轻，反代和防火墙都友好 |
| `res.on('close')` 断开感知 | `routes/chat.js` | 用户点停止时浏览器只是断开连接，服务端必须主动 abort 上游请求 |

## 三、数据

| 技术 | 用在哪 | 作用 |
|---|---|---|
| SQLite（`node:sqlite` 内置模块） | `server/db.js` | 一个文件就是一个库，免装服务、免编译原生模块；关掉进程再启动数据还在 |
| 预编译语句（`db.prepare`） | 所有查询 | SQL 只解析一次，循环插入时更快，也顺手挡了拼接 SQL |
| 表结构设计（`items`） | `schema` | `done` 用 0/1 而不是布尔（SQLite 没有布尔），`created_at` 用 `datetime('now','localtime')` 默认值 |
| WAL 模式 | `PRAGMA journal_mode = WAL` | 读写不互相阻塞，接口并发时不容易锁库 |
| 会话历史表（D1 版） | `worker/schema.sql` 的 `chat_messages` | Worker 是无状态的，历史必须落库，不能像本机那样放内存 Map |

## 四、AI 与工具调用

| 技术 | 用在哪 | 作用 |
|---|---|---|
| DeepSeek `deepseek-chat` | `server/ai/deepseek.js` | 国内直连、OpenAI 兼容协议、原生支持 `tools`，不用翻墙 |
| SSE 上游解析 | `streamCompletion()` | 把模型的流拆成「文字增量」和「工具调用分片」，`arguments` 是一段段拼起来的 |
| Function Calling（JSON Schema） | `server/ai/tools.js` | 用结构化描述告诉模型「有哪些工具、参数是什么」，模型只负责「说」，执行永远在服务端 |
| 两轮工具循环 | `server/ai/agent.js` 的 `liveAgent()` | 模型要工具 → 后端执行 → 结果回填 → 再问一次拿自然语言总结；最多 3 轮防死循环 |
| 坏 JSON 兜底 | 同上 `parseError` 分支 | 模型给错参数不抛异常，当成一次失败的工具结果回填，让它自己改 |
| 系统提示词 + 当前日期 | `SYSTEM_PROMPT` / `currentDatePrompt()` | 定角色和边界；把「今天几号」显式喂给模型，否则它会把「明天」算成 2026-06-11 |
| 会话裁剪 | `HISTORY_LIMIT=8` | 只带最近 8 条历史，避免 token 越滚越贵 |

## 五、部署与工程

| 技术 | 用在哪 | 作用 |
|---|---|---|
| GitHub Pages | 前端 | 推代码自动上线，自带 https，手机能直接打开 |
| GitHub Actions | `.github/workflows/` | CI 跑 24 条测试；Pages 自动部署；容器镜像自动构建；Worker 自动部署 |
| Cloudflare Tunnel | 线上后端 | 不买服务器、不备案，把本机 3000 端口映射成 https 地址（代价：电脑要开着） |
| Docker + GHCR + 阿里云 ACR | 容器方案 | 一条 `docker run` 就能搬到任何云主机；镜像在 Actions 里构建并跑了容器内冒烟 |
| Cloudflare Workers + D1 | `worker/` | Serverless 版后端：免费、地址固定、数据持久（代码就绪，待部署） |
| `node:test` | `tests/` | 24 条用例：16 条接口 + 8 条工具执行器，跑在内存库上不污染数据 |
| puppeteer-core + 本机 Edge | `scripts/` | 自动截图取证 + 9 项端到端冒烟，顺带断言「Console 无报错」「375px 不溢出」 |
| `.env` + `.gitignore` | 根目录 | Key 只在服务端环境变量里，仓库历史零命中（有证据图） |

## 六、三条选型原则

1. **任务书限制优先**：前端只允许原生三件套，所以没碰 Vue/React；这也逼我把「点击 → fetch → 渲染」讲清楚。
2. **少一个依赖少一个坑**：`.env` 解析自己写 20 行、CORS 自己写 20 行、id 生成用 `crypto.randomUUID`，`npm install` 只装 express。
3. **能讲清楚 > 先进**：SSE 比 WebSocket 土，但单向流够用；`node:sqlite` 比 Postgres 土，但一个文件就能跑。

## 七、明确没用/放弃的

| 技术 | 为什么不用 |
|---|---|
| Vue / React / Tailwind | 任务书硬限制；一周时间不够既学框架又学后端 |
| WebSocket | 对话是单向流，SSE 更轻；只有双向协作才需要 WS |
| `better-sqlite3` | 原生模块要编译，免费容器里容易装失败；Node 24 内置的 `node:sqlite` 够用 |
| Vercel 跑后端 | serverless 有执行时长上限，SSE 会被截断；且只有 `/tmp` 可写，SQLite 冷启动即丢 |
| 内存存会话（Worker 版） | 每次请求可能是不同 isolate，必须落 D1 |
| ORM | 表只有一张，手写 SQL 更直观，也更好讲 |
